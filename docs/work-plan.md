# תוכנית עבודה וחלוקה למשימות

## הנחות

- **ההערכות** הן למפתחת שמכירה את הטכנולוגיות (.NET, EF Core, SQL Server, Angular), בעבודה עם עוזר AI לכתיבת קוד. הן כוללות זמן לבדיקה ולהבנה של הקוד, לא רק לכתיבה.
- **יחידת ההערכה:** שעות.
- **המבנה:** 13 פיצ'רים (F0–F12). כל פיצ'ר מחולק למשימות, והערכת הפיצ'ר היא סכום המשימות שלו.
- **בכל משימה:** מה נדרש, התוצר, תלויות, הערכה, איזו דרישה באפיון היא מכסה, ו‑✓ אם היא אינה כתיבת קוד (תכנון, מדידה, תיעוד).
- **כל משימה מסתיימת בבדיקה:** בנייה בלי אזהרות, ובדיקה ידנית או אוטומטית של התוצר.

## סדר ביצוע ותלויות

```
F0 תכנון
 └─ F1 מודל נתונים ו-Seed
     └─ F2 API לשליפה
         ├─ F3 אינדקסים ──────────── F11 ביצועים
         ├─ F4 טיפול שגיאות
         └─ F5 עדכון סטטוס + Concurrency
             ├─ F6 היסטוריה
             │   └─ F7 Bulk
             └─ F8 Cache (Invalidation בכל עדכון)

F9  Angular   ← אחרי F2 (רשימה), F5–F7 (עדכון, היסטוריה, Bulk)
F10 בדיקות    ← אחרי F2, F5, F7, F8
F12 תיעוד ו-Git ← בסוף
```

- **מה אפשר במקביל:** אחרי F2, הענפים F3/F11, F4 ו‑F5–F8 לא תלויים זה בזה. בצוות, Angular (F9) יכול להתחיל מיד אחרי F2, מול החוזה של ה‑API, ולהתקדם במקביל לשרת.
- **למה F3 (אינדקסים) מיד אחרי F2:** את האינדקסים מתכננים לפי השאילתות האמיתיות של השליפה, ומודדים לפני ואחרי.
- **למה F8 (Cache) אחרי F5:** ה‑Invalidation נבנה על נקודות העדכון. בלי עדכונים אין מה לבטל.
